MAX Front App — это шаблон для разработки мини-приложений внутри мессенджера MAX на основе React и Vite. В проекте используется архитектура Feature-Sliced Design (FSD), которая предусматривает разделение кода на слои по их назначению

Шаблон позволяет:

- Создавать мини-приложения с готовой структурой проекта
- Запускать приложение локально, в том числе с тестовыми данными без подключения к серверу
- Настраивать адрес сервера API и подключение WebApp Bridge через переменные окружения
- Выполнять запросы к API через общий обработчик
- Управлять темой приложения и сохранять выбранные настройки
- Показывать уведомления разных типов с настройкой их расположения
- Проверять код, собирать проект и анализировать размер сборки

## 1. Создание проекта

Для создания проекта из шаблона используйте утилиту командной строки (CLI):

```bash
@maxhub/create-max-front-app my-new-project
```

Подробнее об использовании утилиты — [в инструкции по CLI](./cli/docs/usage.md)

## 2. Локальный запуск и проверка проекта

Установите зависимости проекта:

```bash
npm install
```

Запустите локальный сервер разработки:

```bash
npm run dev
```

Запустите приложение с тестовыми данными без подключения к серверу API:

```bash
npm run dev-mock
```

Проверьте типы и запустите сборку проекта:

```bash
npm run build
```

Проверьте код с помощью ESLint:

```bash
npm run lint
```

Локально откройте собранное приложение:

```bash
npm run preview
```

Проанализируйте размер сборки:

```bash
npm run analyze
```

Команда формирует отчёт `stats.html` с интерактивной схемой, показывающей состав и размеры частей сборки

## 3. Настройка переменных окружения

Для локальной настройки приложения используются переменные из файла `.env`. Пример их значений приведён в папке `.env.example`:

```env
VITE_API_HOST=host
VITE_BRIDGE_URL=bridge
VITE_MOCK=false
```

Назначение переменных:

- `VITE_API_HOST` — адрес сервера API, на который отправляются запросы через `apiRequest`
- `VITE_BRIDGE_URL` — адрес скрипта WebApp Bridge (SDK MAX)
- `VITE_MOCK` — включение режима работы с тестовыми данными без подключения к серверу API. Команда `npm run dev-mock` устанавливает это значение автоматически

При запуске приложение проверяет переменные окружения в `src/shared/config/config.ts`

- Если включён режим тестовых данных (`VITE_MOCK=true` или `npm run dev-mock`), проверка переменных не выполняется. Приложение использует локальные тестовые данные без обращения к серверу API
- Если режим тестовых данных выключен, переменные `VITE_API_HOST` и `VITE_BRIDGE_URL` обязательны
- Пустые значения, значения `host` и `bridge` из `.env.example`, а также адреса без схемы `http://` или `https://` считаются ошибочными

Если проверка завершилась с ошибкой, вместо приложения отображается экран `EnvErrorScreen` со списком переменных, которые необходимо исправить. Это работает при разработке и в уже собранном приложении. Дополнительная информация об ошибках выводится в консоль через `console.error`

## 4. Структура проекта

Проект организован по архитектуре Feature-Sliced Design (FSD), которая предусматривает разделение кода на слои по их назначению

**Основная структура каталога `src/`**

| Путь | Назначение |
| --- | --- |
| `src/app/` | Точка входа в приложение, подключение провайдеров, настройка маршрутизации и глобальных стилей |
| `src/app/providers/` | Подключение провайдеров приложения (`AppProviders`) |
| `src/app/router/` | Настройка маршрутизации (`AppRouter`) |
| `src/app/App.tsx` | Основной компонент приложения |
| `src/app/main.tsx` | Точка входа в приложение |
| `src/app/global.css` | Глобальные стили |
| `src/entities/` | Бизнес-сущности приложения |
| `src/entities/dog/api/` | API-запросы и типы сущности `dog` |
| `src/entities/dog/model/` | Хуки, запросы, операции изменения данных, ключи запросов и тестовые данные сущности |
| `src/entities/dog/ui/` | Компоненты интерфейса сущности `dog` |
| `src/features/` | Отдельные переиспользуемые функции приложения |
| `src/features/toggle-theme/` | Функция переключения темы |
| `src/pages/` | Страницы приложения, состоящие из сущностей, функций и общих компонентов |
| `src/pages/Main/` | Каталог страницы `Main` |
| `src/shared/api/` | Общая обработка HTTP-запросов через `fetch`, ошибок и режима тестовых данных |
| `src/shared/bridge/` | Интеграция с WebApp Bridge (SDK MAX) |
| `src/shared/config/` | Конфигурация переменных окружения |
| `src/shared/lib/` | Общие вспомогательные функции |
| `src/shared/theme/` | Управление темой приложения |
| `src/shared/toast/` | Система всплывающих уведомлений |
| `src/shared/ui/` | Переиспользуемые компоненты интерфейса |

## 6. Интеграция с WebApp Bridge

Для загрузки WebApp Bridge (SDK MAX), обеспечивающего взаимодействие мини-приложения с мессенджером, используйте функцию:

```ts
loadBridge()
```

Для получения уже загруженного объекта WebApp используйте функцию:

```ts
getBridge()
```

Для работы с WebApp Bridge в компонентах предусмотрены `BridgeProvider` и хук `useBridge`:

```ts
import { BridgeProvider, useBridge } from '@/shared/bridge'

const { status, webApp, initData } = useBridge()
```

> Для авторизации используйте только `initData` из `WebApp`. Не используйте `initDataUnsafe` для авторизации

## 7. Работа с API

Для отправки запросов к API используется общий обработчик `apiRequest`, расположенный в файле `src/shared/api/api.ts`

Пример запроса:

```ts
import { apiRequest } from '@/shared/api'

const dogs = await apiRequest<Dog[]>('/dogs', { method: 'GET' })
```

Обработчик `apiRequest`:

- Автоматически добавляет заголовки `Accept` и `Content-Type`
- Позволяет переопределять адрес сервера через необязательный параметр `baseUrl` в `ApiRequestOptions`
- При `VITE_MOCK=true` перехватывает запросы через `mock-registry` и возвращает локальные тестовые данные без обращения к сети
- При ошибке ответа создаёт типизированную ошибку через `createApiRequestError`

Запросы, относящиеся к конкретной сущности, размещаются в её каталоге `api/`, например `src/entities/dog/api`

## 8. Управление темой

Компоненты управления темой находятся в каталоге `src/shared/theme/`

`AppThemeProvider` подключает компонент `MaxUI` из библиотеки `@maxhub/max-ui` и передаёт ему настройку цветовой схемы через `colorScheme`

Цвета интерфейса доступны через CSS-переменные MaxUI, например `--text-primary` и `--background-surface-floating`

Для получения текущей цветовой схемы и её переключения используйте хук `useAppTheme`:

```ts
import { useAppTheme } from '@/shared/theme'

const { colorScheme, toggleColorScheme } = useAppTheme()
toggleColorScheme()
```

Выбранная тема сохраняется в `localStorage` и восстанавливается при следующем открытии приложения

## 9. Уведомления

В приложении предусмотрена общая система всплывающих уведомлений (`toast`). Поддерживается четыре типа уведомлений:

- `success` — успешное выполнение операции
- `error` — ошибка
- `warning` — предупреждение
- `info` — информационное сообщение

Уведомления можно размещать в верхней (`top`) или нижней (`bottom`) части экрана. Одновременно в каждой из этих областей отображается не более пяти уведомлений

Уведомления поддерживают автоматическое закрытие по таймеру, закрытие вручную и анимации появления и исчезновения

Поскольку провайдер уведомлений подключён внутри `AppThemeProvider`, их оформление автоматически меняется при переключении темы приложения

Для показа уведомления используйте хук `useToast`:

```ts
import { useToast } from '@/shared/toast'

const toast = useToast()

toast.show({
  type: 'error',
  placement: 'top',
  title: 'Ошибка',
  description: message,
  duration: 4000
})
```

В примере создаётся уведомление об ошибке в верхней части экрана с длительностью отображения 4000 мс

## 10. UI-компоненты

Переиспользуемые компоненты интерфейса находятся в каталоге `src/shared/ui/`:

- `Modal` — модальные окна
- `FlexBox` — компонент для размещения элементов с помощью Flexbox
- `Page` — базовый компонент разметки страницы
- `Toast` — компоненты отображения уведомлений
